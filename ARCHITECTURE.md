# theodolite: architecture

## Modules

- `src/cli.ts` routes four commands; each command is one module with a `run(argv)`.
- `src/scan/` is the matrix: `matrix.ts` parses and validates `theodolite.toml`, `walk.ts` lists source files, `presets/` turn source text into write sites per language, `resolve.ts` maps sites to resources and produces findings, `output.ts` formats them, `scan.ts` ties it together for `check` and `report`.
- `src/init/` copies `templates/` into a repository without overwriting, merging `.claude/settings.json`.
- `src/status/` is the Stop and SubagentStop hook: one plain line per turn into STATUS.md.
- `src/shared/` holds the TOML parser wrapper, the file-read helper and the version constant.

## Data flow

`theodolite.toml` → `matrix.ts` → `walk.ts` → preset detectors → `resolve.ts` → findings → `output.ts` (text, JSON, or the section below). Nothing is written during `check` or `report`.

## Nouns

Resource (a table, an external API, a side effect, a queue, a bucket, a path), writer (a glob of files), constructor (the one path that creates an aggregate), connection (who may hold a client), write site (file, line, call, target), finding (a site with no declared writer).

## One-way doors

Changing the `theodolite.toml` schema; changing an output format other users parse in CI; adding a dependency.
